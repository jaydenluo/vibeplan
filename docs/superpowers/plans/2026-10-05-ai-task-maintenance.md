# AI 任务维护轻量优化实施计划

**目标：** 让 AI 在已授权的软件开发任务中维护上下文、字段、阻塞和修复进展，减少用户手动填报。

**方案：** 使用现有任务、计划 Markdown、事件、版本锁、报告和验收周期，不新增数据库表或页面菜单。相较完整 GitHub 集成及容量管理，先提供 CLI 可直接使用的上下文和更新能力；验收失败优先修复原任务，独立新增需求仍需明确授权。用户已要求制定方案并实施，本文件记录本轮授权范围。

## 实施步骤

- [x] CLI `task:context ID`：一次取回最新任务，整理计划、最近事件、当前验收问题、退回原因和下一步提示；读取本地 Git 分支和改动候选，仅作上下文，不推断测试或完成状态。
- [x] CLI `task:update ID --task-version N --file patch.json`：严格校验支持字段，拒绝未知字段及直接完成/进入评审；检查本地项目和服务器归属，复用幂等更新队列。AI 可修改计划字段和依赖，记录阻塞、解除阻塞。
- [x] CLI `task:report --git-base SHA`：只采集指定 Git 基线之后的提交文件及 HEAD，无提交则不冒充代码证据；显式 changedFiles 可进一步限制范围，脏工作区提示不会自动计入。只读 Git，不自动 commit/push，不读取 remote 凭据。
- [x] Skill：自动执行已授权范围内的上下文读取、进展/字段维护、同任务修复、真实报告；优先使用原任务验收周期，用户仍负责验收。阻塞阶段同时写 blocked 状态；恢复使用 task:update。决策与交接内容写入已有计划，不添加新必填字段。
- [x] 中英文教程：用户正常使用 start 和自然语言，维护命令由 AI 执行；明确 daemon 负责同步，不读取任意对话、不自主运行代码；升级 CLI 后刷新托管 Skill。
- [x] 验证：上下文排序/当前周期、错误字段/越权状态、跨项目保护、Git 真实临时仓库范围、CLI 构建/帮助、原执行测试、模板与打包验证。完成后记录变更、证据和限制。

## 验收与范围

AI 能读出退回原因并在原任务修复；字段更新保留版本冲突/离线队列机制；Git 采集不把未提交文件当成已提交，不自动验收、不生成虚假工时/测试。网页继续使用已有进度、计划、验收和报告展示。复杂容量排期、自动 PR/CI webhook、评审截图上传和独立通知中心留作未来需求，不在本轮引入。
