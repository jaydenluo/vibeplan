# VibePlan 平台管理员后台设计

## 目标

在现有 VibePlan Web 应用中提供独立的 `/admin` 运营路由。平台管理员可查看全站用户、组织与支付宝订单，管理平台管理员名单，并保留所有敏感管理动作的审计记录。

## 已确认范围

- 不创建单独前端项目或独立域名，复用当前登录态与 Web 部署。
- Web 左侧导航只对平台管理员显示“管理后台”。直接访问 `/admin` 的非管理员由 API 和前端拒绝。
- 首批超级管理员由服务器 `.env` 的 `PLATFORM_ADMIN_EMAILS` 配置。
- 超级管理员可以授予或撤销普通平台管理员；最后一个超级管理员不能被撤销。
- 一期仅提供用户、组织、订单/充值记录查询和管理员管理；不提供退款、手工改价、人工开通订阅、删除用户或修改支付订单。
- 订单记录是已创建的订阅订单，不将浏览器回跳视为充值成功；付款状态以支付宝异步通知验签后的订单状态为准。

## 权限模型

`platform_admins` 表保存持久化授权，字段包括用户 ID、`super_admin` 或 `operator` 级别、授权人、授权时间、撤销人、撤销时间。环境变量匹配的已登录用户视为超级管理员，即使数据库还没有首次授权记录；系统在首次管理请求时幂等写入审计授权记录。

- `super_admin`：查看后台全部数据，管理管理员名单。
- `operator`：查看后台全部数据，不能改变管理员名单。
- 普通组织 owner/admin/member：没有平台后台权限。组织角色不会提升为平台管理员。

所有 `/admin/*` API 都先验证登录，再通过 `PlatformAdminService` 校验平台角色。客户端绝不能单独决定访问资格。

## 数据与 API

### 新表

`platform_admins`

- `user_id`（唯一外键）
- `role`：`super_admin` / `operator`
- `granted_by_user_id`（首个环境变量管理员使用其自身）
- `revoked_at`、`revoked_by_user_id`
- 创建与更新时间

`platform_audit_logs`

- `actor_id`、`action`、`target_type`、`target_id`
- 不含密码、JWT、支付宝签名或私钥的结构化 `metadata`
- 创建时间

### API

- `GET /admin/me`：返回当前平台管理员身份。
- `GET /admin/overview`：用户数、组织数、活跃订阅数、近 30 天已付款金额、待付款订单数。
- `GET /admin/users?q=&cursor=&limit=`：按姓名或邮箱搜索；返回注册时间、最后登录、组织数量与管理员身份。
- `GET /admin/organizations?q=&planCode=&state=&cursor=&limit=`：返回组织、所有者、套餐、成员/项目用量、到期/宽限状态。
- `GET /admin/orders?q=&status=&planCode=&from=&to=&cursor=&limit=`：返回订单号、组织、购买人、套餐、金额、状态、支付宝交易号与付款时间。
- `GET /admin/admins`：管理员名单。
- `POST /admin/admins`：仅超级管理员授予既有用户平台权限。
- `DELETE /admin/admins/:userId`：仅超级管理员撤销普通平台管理员；禁止撤销环境变量超级管理员和最后一个有效超级管理员。

列表 API 使用服务器端筛选、稳定排序与限制在 1–100 的分页，避免一次性向浏览器发送全部用户或订单。读取敏感用户/订单列表和管理员授权变更均产生审计日志。

## Web 体验

平台后台的受众是运营人员，首屏任务是快速识别订阅和付款风险。视觉保持既有冷静、紧凑的工作台，但引入一个清晰的“运营”标记作为区分：深青标题、浅青数据状态线和琥珀色待处理指标；不使用营销卡片或大面积装饰。

```
左侧导航
  总览 / 团队 / 项目 / 审批 / 任务
  ─────────────────────────
  管理后台 (仅平台管理员)

/admin
  运营概览 | 用户 | 组织 | 充值记录 | 管理员
  指标条（注册用户、有效订阅、30 天收入、待确认）
  筛选行 + 可扫描表格 + 服务器分页
```

后台分为五个标签：概览、用户、组织、充值记录、管理员。用户和组织行只显示运营必要字段；点击行展开侧栏查看关联组织或订单，不在列表中堆叠敏感信息。充值记录的交易号默认截断显示并可复制，金额统一以人民币元显示。管理员页仅超级管理员显示授权和撤销动作；普通运营管理员只读。

移动端将指标改为两列、表格保留三项主信息并提供“查看详情”展开，不依赖横向溢出完成关键判断。

## 审计与安全

- 绝不在 API 或前端返回密码哈希、刷新令牌、邮箱验证码、支付宝签名、私钥或完整支付通知载荷。
- 管理员 API 统一记录 actor、动作、对象及非敏感元数据；列表审计按一次请求记录筛选条件和结果数量，不逐行产生噪音。
- 管理员授权只能针对已注册用户的邮箱，服务端查找用户后再写入记录。
- 环境变量是紧急/首次引导权限，修改后重启 API 生效；数据库授权不会覆盖环境变量超级管理员。

## 测试

- API：非管理员访问所有 `/admin/*` 返回 403；环境变量超级管理员和数据库 operator 的能力区分正确；分页和筛选不泄漏其它字段；管理员变更写审计并保护最后一个超级管理员。
- 数据：管理员表唯一性、撤销逻辑与审计表迁移幂等。
- Web：普通用户看不到菜单并拒绝 `/admin`；管理员可查看概览、搜索订单、筛选状态；非超级管理员没有授权控制。
- 运行：`vibeplan check`、相关 Vitest、`pnpm -r build`、`git diff --check`。

## 非目标

退款、手工支付确认、价格修改、订阅直接编辑、删除用户、导出全量个人数据、财务发票和多租户数据隔离不在一期范围。
