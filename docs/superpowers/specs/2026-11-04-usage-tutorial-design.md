## 需求与推荐

在主菜单的“待办审批”之后增加“使用教程”。正文由项目内的 Markdown 文档维护，支持图片、章节大纲导航与代码语法高亮。

推荐复用根目录 `user-guide.md` 作为唯一正文来源，维护者可以在编辑器中直接修改。网页提供排版后的阅读界面；开发时保存文档后更新预览，线上内容在重新构建、发布后更新。

“直接编辑”在本方案中指维护者编辑仓库里的 MD 文件。这是待用户确认的方案选择，不代表已经确认要在网页中编辑文档。

## 可选方案

| 方案 | 内容维护 | 更新方式 | 适用情况 |
| --- | --- | --- | --- |
| 推荐：仓库 Markdown + 阅读页 | 编辑 `user-guide.md` 和配图 | 本地开发预览，线上重新发布 | 维护成本低，保留 Git 版本记录 |
| 网页 Markdown 编辑器 + 阅读页 | 授权维护者在网页编辑、预览、保存 | 保存后在线生效 | 需要编辑权限、持久化、并发冲突处理与图片上传 |
| 独立文档站 | 单独维护文档工程 | 独立发布 | 适合以后扩展多篇教程、搜索与多版本文档 |

本次推荐第一种。若用户需要网页编辑保存，应先把相应范围纳入任务再实施。

## 页面与交互

- 菜单入口为“使用教程”，使用书本图标，与现有菜单保持相同选中、展开、收起和移动端行为。
- 页面路由建议为 `/guide`，支持直接访问、刷新、浏览器前进和后退。
- 桌面端沿用左侧全局菜单；中间为有合理阅读宽度的正文；右侧为固定可见的“本页大纲”。
- 大纲根据二、三级标题自动生成，按标题层级缩进；点击跳转到章节；滚动阅读时高亮当前章节。
- 中文标题、重复标题、含行内代码的标题生成稳定且不冲突的锚点；复制带锚点地址后可直接进入该章节。
- 窄屏时大纲改为正文上方的可折叠“目录”，正文不产生整页横向滚动。
- 代码块保留语言标签、语法高亮和复制按钮。超宽代码块与表格仅在自身区域横向滚动。
- 图片保持比例、自适应正文宽度，支持替代文本与懒加载；加载失败时保留有意义的替代信息。

## 文档内容

保留已有 `user-guide.md` 的用户修改，按需补充，不另复制一份长期维护的正文。

建议章节顺序：

1. 快速上手：注册、创建组织和项目、安装 CLI。
2. 连接本地项目：登录、绑定项目、启动同步。
3. 与 AI 协作：安装助手规则、需求规划、创建和执行任务。
4. 跟踪执行：详细计划、进度、阻塞、执行报告。
5. 人工验收：待审核条件、逐项验收、批准完成、退回修改。
6. 团队协作：成员、权限、分工与工时记录。
7. 常用命令与常见问题。

首版使用少量有说明文字的真实截图，重点说明项目入口、任务详情与验收流程。截图需要与当前实际版本一致，避免把个人账号信息当作公开教程素材。

## 实现方案

- 新增独立的教程页组件，接入 `WorkspacePage.tsx` 现有路由逻辑，不扩大改动到其他页面的 Markdown 展示。
- 推荐使用 `react-markdown`、`remark-gfm` 和 `rehype-highlight`，支持常见 Markdown、表格、任务清单和代码高亮。教程页与高亮依赖按需加载。
- 在同一 Markdown 解析流程中生成标题锚点和大纲，避免两套解析规则造成标题或链接不一致。
- 复用 `user-guide.md`，可通过 Vite 的原文导入能力加载；发布产物包含正文，不依赖运行时访问本机仓库。
- 配图建议统一放在 `apps/web/public/guide/images/`，提供明确的 Markdown 图片路径示例。处理站点基础路径，保证生产构建后图片仍可访问。
- 保持默认安全 Markdown 渲染，关闭原始 HTML 执行，限制危险链接协议。仓库文件链接如 `LICENSE` 需显式映射到可访问地址，不能直接跳到不存在的应用路由。
- 未标注或不支持的代码语言回退为普通代码块，不影响正文显示；加载失败时提供重试入口。
- 页面为所有已登录用户提供统一教程，不依赖是否选择了组织、团队或项目。
