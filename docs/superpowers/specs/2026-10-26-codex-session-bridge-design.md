# Codex 会话桥接与任务执行设计

## 目标

让 Vibe Plan Web 能够管理本地 Codex 工作会话：用户可以创建新的 Codex 会话，也可以选择已经显式绑定的历史 Codex 会话，将 Vibe Plan 任务交给它执行，并在 Web 中查看在线状态、当前任务、日志和执行结果。

## 范围

本次设计包含：

- 本地设备与项目代理注册
- Codex 会话的创建、发现、绑定、解绑和状态同步
- Web 会话列表与会话选择
- 将已授权任务分配给指定会话
- 执行日志、进度、成功/失败和取消状态回传
- 网络断开后的心跳、恢复和防重复执行
- 会话及任务操作的权限校验和审计

本次设计不包含：

- 自动扫描用户所有本地聊天记录
- 绕过 Codex 桌面应用权限直接读取私有会话
- 自动执行未在 Vibe Plan 中授权的任务
- 自动提交、推送、发布或部署代码

## 核心概念

### 本地设备

一个运行 Vibe Plan Agent 的电脑。设备使用一次性配对码或设备令牌注册到当前用户，并定期发送心跳。设备包含可用项目目录和 Agent 版本信息。

### 工作会话

Vibe Plan 对一个本地 Codex 执行上下文的稳定引用。会话字段包括：

- `id`：Vibe Plan 会话 ID
- `provider`：`codex`
- `providerSessionId`：Codex 提供的会话标识，允许为空直到首次创建
- `deviceId`
- `projectPath`
- `projectId`
- `status`：`offline`、`idle`、`running`、`paused`、`error`
- `currentTaskId`
- `lastHeartbeatAt`
- `createdAt`、`updatedAt`
- `source`：`created` 或 `imported`

历史 Codex 会话只有在本地 Agent 获得用户明确授权并完成绑定后，才会进入这个列表。

### 执行任务

一次将 Vibe Plan 任务分配给工作会话的操作。执行任务使用任务当前版本、项目绑定和授权范围创建不可变快照，并生成 `executionId`。同一个 `executionId` 只能启动一次，网络重试必须复用它，避免重复执行。

## 建议架构

```text
Vibe Plan Web
    │ HTTPS / SSE
    ▼
Vibe Plan API ── 会话、授权、任务快照、日志、审计
    ▲
    │ Agent 主动建立的 WebSocket 或长轮询连接
    ▼
本地 Vibe Plan Agent
    │
    ├─ 项目目录和 Git 状态
    ├─ 新建 Codex CLI 会话
    └─ 显式绑定的已有 Codex 会话
```

Agent 主动连接云端，云端不直接访问用户电脑端口。这样适用于家庭网络、公司内网和 NAT 环境，也不会要求开放本地端口。

## 会话流程

### 启动 Agent

1. 用户在本机运行 `vibeplan start`，Agent 使用已保存的登录凭据连接 API。
2. Agent 注册设备、已绑定项目和 Agent 能力。
3. Agent 上报本机可用 Codex 会话。
4. API 返回会话授权范围和待处理命令。
5. Agent 每 15 秒发送心跳；超过约 45 秒没有心跳，Web 显示为离线。

### 新建会话

1. 用户在 Web 选择设备、项目目录和“新建 Codex 会话”。
2. API 创建工作会话记录，状态为 `idle`，生成一次性启动命令。
3. Agent 收到命令后，在指定项目目录启动受控 Codex 会话。
4. Agent 回传 `providerSessionId` 和能力信息。
5. Web 将会话显示为可用。

### 绑定已有会话

1. 用户在本机 Codex 中选择“绑定到 Vibe Plan”，或执行 Agent 提供的一次性绑定命令。
2. Agent 只提交该会话的标识、项目路径和用户确认结果。
3. Web 显示待确认的绑定请求。
4. 用户确认后，API 创建 `source=imported` 的工作会话。
5. 后续 Web 只能向已绑定的会话发送任务。

如果 Codex 当前版本没有公开会话枚举或恢复接口，Agent 只能提供“当前 Agent 启动的会话”和用户主动导入的会话；系统不能可靠地读取 Codex 私有历史数据库。

### 执行任务

1. 用户在任务页面选择会话并点击“开始执行”。
2. API 检查用户对项目和任务的权限、任务版本、项目路径和会话在线状态。
3. API 创建不可变任务快照和 `executionId`，状态为 `queued`。
4. Agent 接收命令，确认项目路径和快照哈希后开始执行。
5. Agent 上报阶段、日志、测试结果和结构化报告。
6. API 根据幂等键处理重复消息，Web 通过 SSE 查看实时状态。
7. 成功结果进入任务的 `in_review`，不会自动标记完成；取消、失败和阻塞都保留完整原因。

## API 草案

### 会话

- `GET /agent/sessions`：当前用户可见的会话列表
- `POST /agent/sessions`：创建新会话
- `POST /agent/sessions/:id/bind`：确认绑定已有会话
- `POST /agent/sessions/:id/unbind`：解除绑定
- `POST /agent/sessions/:id/stop`：停止当前会话任务
- `GET /agent/sessions/:id/events`：会话事件和日志流

### 执行

- `POST /agent/sessions/:id/executions`：创建任务执行快照
- `GET /agent/executions/:id`：查看执行状态
- `POST /agent/executions/:id/cancel`：请求取消
- `POST /agent/executions/:id/events`：Agent 上报幂等事件

Agent 通道使用独立的短期连接令牌。浏览器会话令牌不直接下发给本地进程。

## 安全与授权

- 所有会话必须属于当前用户，并绑定一个明确项目目录。
- 任务执行必须使用任务当前版本；版本变化时拒绝启动。
- Agent 只执行 API 下发的冻结快照，不把任务文本当作 shell 命令。
- 项目目录必须通过本地绑定文件校验，禁止 Web 任意指定路径。
- 新建、导入、执行、停止、解绑都写入审计事件。
- 默认禁止自动接受任务；执行成功后进入人工审核。
- 设备令牌可撤销，绑定请求一次性且短时有效。
- 日志中的环境变量、密钥和访问令牌必须脱敏。

## 断线与失败处理

- Agent 连接断开后，API 将会话标记为 `offline`，不自动启动新的执行。
- 已经开始的执行保留 `executionId` 和最后确认的事件序号。
- Agent 重连后先发送能力和执行检查，再从最后确认序号继续上传日志。
- API 对命令和事件使用幂等键，重复消息只确认不重复执行。
- 无法确定远端是否已经执行的命令进入 `needs_reconciliation`，要求用户查看本地状态后恢复；不能盲目重放。

## Web 交互

任务详情增加“执行会话”选择器，显示：设备、项目目录、Codex 会话名称、状态、最后在线时间和当前任务。

选择“新建会话”时显示设备和项目目录；选择已有会话时只显示已绑定会话。执行面板显示阶段、实时日志、测试结果、取消按钮和断线提示。会话列表按在线状态、当前项目和最近使用时间排序。

## 分阶段实现

### 第一阶段：可靠的 Vibe Plan 会话

- Agent 注册设备和项目
- API 会话表和心跳
- Web 会话列表
- 新建 Codex CLI 会话
- 将已授权任务交给新建会话执行
- 执行日志和幂等状态

### 第二阶段：复用与恢复

- 会话长期绑定项目
- 断线恢复和取消
- 会话事件流
- 任务执行历史和审计页面

### 第三阶段：已有 Codex 会话导入

- 本地显式绑定流程
- Codex 会话能力探测
- 导入会话的恢复和兼容性处理
- 对不支持恢复的版本提供清晰降级提示

## 验收标准

1. Web 能列出当前用户已授权且在线的本地 Codex 会话。
2. 用户能从 Web 创建新会话，并看到其变为 `idle`。
3. 用户能将一个已授权任务分配给指定会话，并看到日志和状态变化。
4. 同一执行命令重试不会重复启动任务。
5. 任务版本或项目绑定变化时，执行会被拒绝。
6. Agent 断线后会话显示离线，重连能恢复状态和日志位置。
7. 未经用户明确绑定的 Codex 历史会话不会出现在 Web 列表中。
8. 执行成功进入人工审核，不自动完成任务。

## 风险

- Codex 桌面应用如果没有稳定的本地会话接口，历史会话导入只能通过显式插件或绑定命令完成。
- 本地 Agent 执行 AI 代码修改具有高权限，必须限制项目目录和命令来源。
- 长连接断线时最难确认的是“命令是否已经在本地开始”，需要依赖幂等键和人工 reconciliation。
