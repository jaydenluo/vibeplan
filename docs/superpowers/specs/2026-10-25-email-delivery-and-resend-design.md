# 邮件投递与重发设计

## 目标

注册验证码与密码重置邮件只能在邮件服务已完整配置且 SMTP 服务实际接受投递时显示成功。用户在成功发送验证码后，30 秒内不能重新发送，即使刷新注册页面也不会绕过该限制。

## 范围

- 使用 SMTP 发送注册验证码、邮箱验证和密码重置邮件。
- 在服务端检查邮件配置，并在每次需要投递邮件前阻止未配置或配置无效的发送。
- 在网页端统一显示中文结果，不回显 SMTP 错误详情或凭据。
- 为注册验证码增加 30 秒会话级重发倒计时。

不在本次范围内：邮件投递队列、失败自动重试、第三方邮件服务商 API 和跨设备的重发倒计时同步。

## 配置与运行时行为

SMTP 配置由以下环境变量组成：`SMTP_HOST`、`SMTP_PORT`、`SMTP_USER`、`SMTP_PASSWORD`、`SMTP_FROM`、`APP_BASE_URL`。端口必须是有效的 TCP 端口；465 端口使用 TLS，其他端口使用 STARTTLS 或由 SMTP 服务协商。`APP_BASE_URL` 必须是 `http` 或 `https` 地址，用于生成密码重置链接；线上既有 `VIBE_PLAN_DOMAIN` 可作为它的兼容回退。

应用启动时构造 SMTP 邮件服务。缺少或无效配置不会让应用启动失败，但任何需要发送邮件的请求都会失败并返回 `EMAIL_DELIVERY_NOT_CONFIGURED`。这样管理员可正常登录并补充配置，而用户不会收到错误的“发送成功”提示。

邮件服务会在发送前确认配置，在 SMTP 投递失败时返回 `EMAIL_DELIVERY_FAILED`。错误响应不包含主机、用户名、密码或 SMTP 原始错误详情。

## 接口行为

`POST /auth/register/request-code` 在创建验证码记录前检查邮件服务。配置不可用或投递失败时不创建验证码记录。

`POST /auth/password/request` 在查询用户前检查邮件服务。配置不可用或投递失败时不创建密码重置令牌。即使邮箱未注册，配置可用时接口仍返回成功，以保留账户枚举防护。

邮箱验证被关闭时，注册流程不依赖 SMTP，保持现有直接注册行为。

`GET /auth/config` 增加 `emailDeliveryConfigured`，供注册页面在验证码模式下显示邮件服务状态。服务端的发送前检查仍是唯一安全边界。

## 网页行为

注册页面加载后读取 `emailDeliveryConfigured`。配置不可用时禁用“获取验证码”，并显示“邮件服务尚未配置，请联系管理员。”

发送成功后，网页将 `Date.now() + 30 秒` 写入 `sessionStorage`。按钮在剩余时间内禁用并显示“30 秒后重新发送”；倒计时归零后显示“重新发送”。重新发送成功后更新时间点。页面刷新会从 `sessionStorage` 恢复剩余时间；关闭浏览器会话后可重新请求，服务端限流仍作为保护。

只有接口成功才启动倒计时。配置错误、投递失败、网络失败或请求限流都不会开始计时，并由全局消息中心显示中文错误。

密码重置页只在接口成功后显示“如果该邮箱已注册，重置邮件已发送，请检查收件箱。”

## 错误与提示

| 错误码 | 网页中文提示 |
| --- | --- |
| `EMAIL_DELIVERY_NOT_CONFIGURED` | 邮件服务尚未配置，请联系管理员。 |
| `EMAIL_DELIVERY_FAILED` | 邮件发送失败，请稍后重试或联系管理员。 |

SMTP 原始错误仅保留在服务端日志中，日志不得记录 SMTP 密码、邮件令牌或完整验证码。

## 测试与验收

1. 缺少 SMTP 配置时，请求注册验证码返回配置错误，不创建验证码记录。
2. 缺少 SMTP 配置时，请求密码重置返回配置错误，不创建重置令牌。
3. SMTP 投递失败时返回投递失败，不创建相应令牌。
4. SMTP 投递成功时保留现有验证码和重置流程。
5. 注册页成功发送后显示 30 秒倒计时、禁用按钮、刷新后持续计时、结束后允许重发。
6. 失败请求不开始倒计时，所有错误均为中文。
7. API、Web 测试和生产构建通过。
