# 任务依赖与变更历史优化设计

## 目标

优化任务详情中的“依赖与历史”Tab，让用户能快速判断当前任务是否被阻塞，同时能够按时间追溯任务变更、执行报告、验收和工作记录。

## 当前问题

- 前置依赖使用原生多选框，任务状态、进度和阻塞影响不可见。
- 依赖编辑和变更历史纵向混排，任务较多时扫描成本高。
- 历史记录主要是日志文本，缺少明确的变更摘要和分类筛选。

## 设计范围

### 依赖关系区域

- 位于 Tab 顶部，显示依赖数量和阻塞摘要。
- 每个依赖以任务行展示标题、状态、进度、负责人和影响状态。
- 未完成且会影响当前任务开始的依赖显示阻塞标记。
- 点击依赖任务可切换当前任务详情。
- 使用“添加依赖”按钮打开任务搜索选择器，替代原生多选框。
- 保留现有依赖保存 API 和版本行为，不改变依赖数据模型。

### 变更历史区域

- 位于依赖区域下方，按时间倒序展示时间线。
- 每条记录显示操作者、时间和分类标题。
- 字段更新显示“字段：旧值 -> 新值”的摘要。
- 执行报告、验收、工作记录和普通字段变更使用不同分类标签。
- 默认折叠详细内容，点击记录后展开。
- 提供全部、字段变更、执行报告、验收记录、工作记录筛选。
- 没有历史时显示明确的空状态。

## 数据与交互

- 依赖任务信息从当前已加载的项目任务列表中读取，避免新增请求。
- 依赖保存成功后更新当前任务版本并刷新依赖摘要；失败时保留用户选择并显示错误。
- 历史筛选只影响前端展示，不改变服务端事件数据。
- 点击依赖任务复用现有任务选择和 URL 状态机制。
- 依赖列表和历史列表分别设置内部滚动，避免整个任务详情页面无限增长。

## 视觉与可访问性

- 依赖状态使用现有状态颜色体系，阻塞状态使用高对比度提示。
- 历史记录使用时间线节点和紧凑摘要，避免卡片嵌套。
- 添加依赖、展开记录和筛选控件提供明确的按钮名称和 `aria` 状态。
- 小屏幕下依赖字段换行，历史筛选保持横向滚动，不造成页面溢出。

## 测试与验收

- 依赖任务显示状态、进度、负责人和阻塞标记。
- 添加、移除依赖仍调用现有保存接口，失败时显示错误。
- 点击依赖任务能切换详情。
- 历史按时间倒序展示，并可按五种分类筛选。
- 历史记录可展开和收起，字段变更摘要正确显示。
- 空依赖、空历史和窄屏布局有明确状态。
- 运行任务详情相关 Vitest 测试、Web 构建和 `vibeplan check`。

## 非目标

- 本次不引入复杂依赖关系图。
- 本次不修改 API 数据模型、事件存储格式或权限模型。
- 本次不增加历史记录的删除、编辑功能。
