# 注册提交校验设计

## 目标

注册按钮在等待验证码、验证码未填写或表单字段不完整时保持可点击。用户点击后在相应字段附近获得中文、可访问且能在移动端使用的完成条件提示。

## 范围

- 将注册表单由浏览器原生阻断改为 React 的提交时校验。
- 姓名、邮箱、密码和验证码模式下的验证码均显示字段级中文错误。
- 验证码尚未发送时提示先获取验证码；已发送但未填写六位验证码时提示填写验证码。
- 自动将焦点移至第一个无效字段。

不在本次范围内：修改服务端注册规则、改变验证码 30 秒重发规则、增加悬停气泡提示，或调整登录表单。

## 交互

提交按钮只会在提交请求期间禁用，防止重复提交。表单使用 `noValidate` 避免浏览器默认英文气泡抢先阻断；提交时会校验所有必填条件，保留每个条件的错误文字，且不会请求 `/auth/register`。

错误会显示在对应控件正下方，并通过 `aria-invalid`、`aria-describedby` 关联输入框。用户重新编辑某个字段时，下一次提交会使用最新值重新判断。验证服务未配置时，验证码模式的提交将提示邮件服务不可用。

## 验收

1. 验证码模式下，未发送验证码时点击“注册”会提示“请先获取邮箱验证码”，且按钮可点击。
2. 空姓名、无效邮箱、少于 8 位的密码和非六位验证码均显示相应中文字段提示，且不发送注册请求。
3. 完整有效的表单保持现有注册请求格式。
4. 提交过程仍防止重复提交，且现有验证码倒计时行为不变。
