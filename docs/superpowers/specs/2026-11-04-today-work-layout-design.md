# 今日工作布局优化建议

日期：2026-11-04
状态：用户已确认布局并授权实施（“好的请帮我改”）；本地实现与针对性验证完成，等待用户检查视觉效果。执行记录见 ../plans/2026-11-04-today-work-layout.md。

## 目标与依据

让当前用户迅速判断下一步做什么、任务属于哪个项目、哪些事项需要自己处理。沿用工作台的蓝灰配色、系统字体和细分隔线。

依据：TodayWork.tsx、OrganizationOverview.tsx、styles.css、myWork 服务及原工作台设计。通过本地真实组件与虚构演示数据复现布局；未读取用户浏览器登录状态。1440px 视口下，五列各约 238px，三条任务列高约 381px，空列也占相同空间。

## 当前问题

1. 五类等宽排列，标题容易折行；空栏目保留整列空间，数量不均时页面失衡。
2. next 来自进行中或可开始队列，同一任务以完整卡片出现两次。
3. 服务返回 projectName，但前端类型与展示未使用它，跨项目任务缺少归属。
4. 标题、说明、分组标题间距分散；刷新按钮过重，视觉层级与上方工作台不统一。
5. 通用推荐原因逐条重复，占据卡片高度；真正的阻塞原因应保留。
6. 每次自动刷新先清空数据，内容消失后恢复；接口失败与真实空列表未区分。
7. “今日工作”目前表示待处理工作队列，并非按当天截止日期筛选；本次不改变其数据含义。

## 可选布局

- 推荐：顶部推荐条 + 分类切换 + 通栏任务列表。宽度充分、容易扫描，其他类别通过数量和标签切换访问。
- 双栏：左侧执行任务，右侧阻塞与验收。可同时看到两类信息，但两侧任务数量不均时仍会留白。
- 保留多列：将推荐项移出，再改为两列/四列响应式。改动小，但长标题、重复卡片式信息和空栏目空间仍需处理。

## 推荐设计

```text
今日工作                                      刷新
当前组织内需要我处理的任务

建议下一步  任务名称 · 项目名称             查看任务 →

进行中 3     可开始 1     已阻塞 0     待验收 1
──────────────────────────────────────────────────
任务名称                    项目      优先级    截止
新增 Markdown 使用教程…     Vibe Plan   P2      11-06
优化任务列表状态提示…        Vibe Plan   P1      11-06
```

- 推荐条最多一项，没有推荐时不占位。推荐任务仍保留在所属分类，数量与接口一致；推荐条只提供快捷入口。
- 四个类别显示数量，当前类别用蓝灰下划线和字重标识。默认进行中；为空时依次选择待验收、已阻塞、可开始。全部为空时显示统一空态。
- 列表使用行式排版，任务标题为主；项目、优先级、截止日期为辅。长标题最多两行，保留完整可访问名称与标题提示。没有日期显示“未设截止”。
- 普通的“优先继续已开始的任务”等通用原因不逐行重复；阻塞原因在任务下方展示，长原因可展开，确保能够完整读取。
- 待验收、阻塞、逾期采用小范围的琥珀或红色文字提示；不整块铺色。
- 默认展示六条，超出时提供“展开全部 / 收起”，不改变服务端排序或队列归属。
- 点击任务继续使用现有 onOpenTask(projectId, taskId)，本次不增加快捷验收、状态修改或其他写操作。
- 刷新使用与工作台一致的图标文字按钮；刷新保留当前内容和分类，只显示更新状态。切换组织时清空旧组织内容，避免混淆。初次失败显示加载失败和重试；后台刷新失败保留旧数据并标明更新失败。
- 窄屏：分类条局部横向滚动；每条任务两行显示，项目、优先级、日期换到次行；不使用整页横向滚动。

## 实施范围与验证

仅修改 TodayWork 组件、对应样式和测试；无需 API、数据库或任务状态规则变化。保留用户其他未提交修改。用户确认本方案后再制定执行计划和实施。

验证包括：分类数量和切换、推荐条与任务定位、projectName、展开更多、空态、失败重试、刷新保留内容、组织切换防串数据；桌面和 375px 手机实际浏览器检查对齐与溢出。运行相关 Web 测试及 Web 类型检查/构建。记录当前已有 styles.test.ts 与用户样式修改不匹配的基线问题，不以隐藏失败方式宣称全量通过。

## 自检

方案限定为今日工作展示及刷新体验；不承诺接口尚未提供的任务完成度，不改变“今日”的筛选含义，不自动创建新 Vibe Plan 任务，不自动提交或发布。
