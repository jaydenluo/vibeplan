# VibePlan 组织订阅与支付宝支付设计

## 目标

让 VibePlan 可以按组织销售年度订阅套餐，并可靠地在服务端实施项目额度、成员额度和到期只读规则。第一版仅支持支付宝主动年度付款，不自动扣款，不提供发票流程。

## 已确认的产品规则

### 套餐

| 套餐 | 年费 | 组织成员上限 | 项目额度 |
| --- | ---: | ---: | --- |
| 个人免费 | ¥0 | 仅所有者 | 同一所有者所有免费组织合计 10 个 |
| 团队 10 人 | ¥480 | 10 | 不限 |
| 团队 30 人 | ¥1,280 | 30 | 不限 |
| 团队 100 人 | ¥3,680 | 100 | 不限 |
| 企业协作 | ¥8,800 | 1,000 | 不限 |
| 定制企业 | 联系我们 | 超过 1,000 | 合同约定 |

订阅属于一个组织，不属于整个用户账号。付费权益不能跨组织使用。同一用户加入同一组织的多个团队时，只按一个组织成员席位计算。

免费组织可创建任意数量的组织和团队，但成员始终只能是所有者：不得创建或接受邀请、加入请求或其他组织成员变更。免费项目额度在同一所有者全部未付费组织间合并计算，避免通过新建组织绕过 10 个项目限制。

仅组织 `owner` 可以查看账单、购买、续费、升级或安排降级。

### 到期、续费和降级

- 用户主动年度续费，不自动续费或自动扣款。
- 订阅到期后有 7 天宽限期。宽限期内保留付费权益，并在产品中明确显示到期风险。
- 宽限期结束后组织进入只读：已有授权成员仍可读取项目和任务；不得创建、编辑、删除项目或任务，不得邀请、接受成员、变更角色或修改团队成员。
- 组织、成员、项目、任务和订单数据均不删除；成功续费后立即恢复写入。
- 降级在当前已付周期结束时生效，不立即降低权益。
- 若降级生效时组织成员数超过新套餐上限，现有成员不删除；系统禁止邀请和组织内写入，直至成员数不超过额度或再次升级。超过额度时同样不允许创建更多组织成员关系。
- 定制企业套餐不提供公开支付入口，由运营人员以受控的手动订阅记录开通。

## 架构

新增 `BillingService` 和 `EntitlementService`。前者管理套餐、订单、支付宝支付请求和通知；后者根据组织订阅、成员数、项目数和当前时间计算可执行操作。所有写操作都在服务端调用权益服务，前端仅用权益摘要控制呈现和给出解释。

```
组织所有者 -> Web 套餐页 -> API 创建订单 -> 支付宝网页支付
                                      |                 |
                                      v                 v
                              billing_orders <- 验签通知 <- notify_url
                                      |
                                      v
                           organization_subscriptions
                                      |
                                      v
         Access / Work-items / Teams / Projects 写入操作 -> EntitlementService
```

支付宝 `return_url` 只用于把用户带回产品页面；订阅状态只以经过验签的 `notify_url` 更新为准。前端回跳后轮询订单或读取订阅摘要，不把回跳参数作为支付成功依据。

## 数据模型

### `organization_subscriptions`

每个组织最多一条当前订阅记录：

- `organization_id`（唯一外键）
- `plan_code`：`free`、`team_10`、`team_30`、`team_100`、`enterprise_1000`、`custom`
- `status`：`free`、`active`、`grace`、`expired`、`scheduled_change`、`manual`
- `period_started_at`、`period_ends_at`、`grace_ends_at`
- `scheduled_plan_code`、`scheduled_effective_at`（用于到期降级）
- `provider` 和 `provider_reference`（支付宝或受控人工开通来源）
- 已购套餐、席位和项目额度快照，以及创建与更新时间

免费组织不需要预先插入记录：权益服务在缺失记录时将其视为 `free`。

### `billing_orders`

不可变订单数据，包含：

- 内部订单号、组织 ID、购买人 ID、计划代码和金额快照（人民币分）
- `pending`、`paid`、`closed`、`failed`、`refunded` 状态
- 支付渠道 `alipay`、支付宝交易号、支付完成时间、对应订阅周期
- 支付页面创建时间、关闭时间、已验证通知时间和必要的审计元数据

金额、计划和组织均由服务端决定，绝不接受浏览器给出的金额。

### `billing_provider_notifications`

保存已验签通知的支付宝交易号、通知标识、载荷摘要、接收时间和处理结果。对交易号建立唯一约束，使支付宝重试或网络重复投递不会重复续费。

订单和通知中的原始敏感字段仅保留满足审计所需的最小范围；私钥、密钥和完整签名材料绝不落库或返回客户端。

## 权益服务

`EntitlementService` 提供一个面向操作的结果，而不是暴露各处自行判断的布尔组合：

- 当前套餐、订阅状态、到期时间、宽限期结束时间
- 已用成员 / 成员上限，已用项目 / 项目上限
- `canWriteOrganization`、`canCreateProject`、`canManageMembers`、`canManageBilling`
- 操作被拒绝时的稳定错误码和面向用户的原因

接入点包括：

- 创建项目：免费组织先按所有者的合并免费项目数检查；付费组织不受项目数限制；到期只读组织拒绝。
- 创建、接收和处理任何组织/团队邀请或加入请求：免费组织拒绝；付费组织要求可写且新增唯一组织成员后不超席位。
- 项目、任务、计划、报告、工时、里程碑、依赖和成员写操作：要求组织可写。
- 删除与修改同样按可写处理，避免过期只读状态仍能通过删除改变数据。
- 所有读取保持既有访问模型，不因到期隐藏已有数据。

服务端是最终约束点；Web 页面只显示升级、续费或成员整理引导，不能成为绕过限制的途径。

## 支付宝流程

1. 所有者在组织设置中选择公开套餐，并确认年度价格。
2. API 验证所有者身份和组织可购买状态，基于服务端套餐目录创建 `pending` 订单。
3. API 使用支付宝 SDK 生成网页支付表单或跳转地址，并绑定内部订单号、固定金额、`notify_url` 与 `return_url`。
4. 浏览器跳转支付宝完成付款。前端回到 VibePlan 后只展示“正在确认付款”及订单查询状态。
5. 支付宝对公开 HTTPS `notify_url` 发出异步通知。API 验证签名、`app_id`、卖家身份、订单号、金额、交易状态和订单所属组织。
6. 一个数据库事务中记录通知、将订单设为 `paid`、创建或延长组织订阅并写入审计事件。
7. 对同一支付宝交易号的重复通知返回成功但不再次延长订阅。

续费在有效期或宽限期内从现有周期末尾延长一年；已经过期的订阅从确认付款时起计算一年。升级立即生效：服务端按当前订阅剩余秒数 / 原付费周期总秒数计算旧套餐未用额度，向下取整到人民币分，用该额度抵扣新套餐年度价格；订单金额为新套餐年费减去抵扣额。支付确认时开始新的完整年度周期。降级始终安排到当前周期结束后。

升级仅允许选择价格更高的公开套餐，且抵扣额不能兑换现金、不能转移到其他组织，也不会因为订单取消而恢复。金额计算、原周期起止时间和抵扣结果写入订单快照，后续不因套餐价格调整而改变。

## 配置与运行

生产环境 `.env` 增加：

```dotenv
BILLING_PROVIDER=alipay
ALIPAY_APP_ID=
ALIPAY_PRIVATE_KEY=
ALIPAY_PUBLIC_KEY=
ALIPAY_GATEWAY=https://openapi.alipay.com/gateway.do
ALIPAY_NOTIFY_URL=https://vibeplan.szxinjin.cn/api/billing/alipay/notify
ALIPAY_RETURN_URL=https://vibeplan.szxinjin.cn/organizations/:organizationId/billing/return
ALIPAY_SELLER_ID=
```

- `.env.example` 只含字段说明和空值；真实 `.env`、私钥和证书不提交 Git。
- API 以生产支付渠道启动时校验全部支付宝字段，缺少字段必须拒绝启动或拒绝创建支付订单并输出明确的安全错误。
- 本地和自动化测试使用 `BILLING_PROVIDER=manual`。该模式只能由管理员显式标记测试订单为已支付，不能在生产环境启用。
- 生产反向代理必须暴露 `notify_url` 的 HTTPS 路由，并保留请求体供支付宝验签；该路由不要求登录，但严格验证来源数据。

## Web 体验

- 组织详情的设置区增加“订阅与账单”入口，显示当前套餐、成员用量、到期日、宽限期或只读状态。
- 所有者看到套餐比较、年度价格、升级/续费/安排降级入口和最近订单；非所有者只看到当前套餐与权限说明。
- 创建项目、邀请成员等被限制的入口显示具体原因和可执行操作，例如“免费项目额度已用完”或“订阅已过宽限期，请续费”。
- 支付返回页轮询订单并给出可恢复的状态：付款已确认、等待支付宝通知、订单关闭或付款失败。不会因为浏览器跳转失败而误判支付失败。
- 定制企业套餐提供联系入口，不创建支付宝订单。

## 错误处理与安全

- 使用稳定错误码：`subscription_read_only`、`free_project_limit_reached`、`member_seat_limit_reached`、`free_plan_membership_locked`、`billing_owner_required`、`payment_configuration_invalid`、`payment_verification_failed`。
- 支付通知按订单、支付宝交易号和金额进行幂等处理；未知订单、金额不符、签名不合法或卖家/应用不匹配均拒绝且记入安全日志。
- 套餐目录和金额仅在 API 配置中定义。客户端传入的套餐代码仅作为选择意图，仍由服务端查询价格与资格。
- 订阅状态按当前时间动态计算，以防定时任务迟到；第一版不依赖定时任务，后续可单独增加到期提醒和展示缓存刷新。
- 历史组织默认免费。部署迁移不会删除现有组织、成员或项目；需要运营人员为既有付费客户建立受控订阅记录。

## 测试与验收

### API

- 免费所有者跨多个免费组织创建第 11 个项目被拒绝；一个组织升级后其项目不再消耗合并免费额度。
- 免费组织创建、接受邀请和加入请求均被拒绝；付费组织在成员上限前可邀请，在上限处被拒绝。
- 同一成员加入多个团队只计一个组织席位。
- 活跃、宽限、过期和超额降级状态的写入与读取权限符合规则。
- 创建订单要求组织所有者，价格由服务端固定，订单状态和订阅变化事务一致。
- 有效支付宝通知激活订阅；重复通知、错误签名、金额不符、错误 `app_id` 或卖家均不会激活订阅。
- 续费、升级、安排降级、定制人工开通和过期恢复具备时间边界测试。

### Web

- 组织所有者可查看套餐和订单，非所有者不能打开管理操作。
- 限额和只读状态的禁用入口与提示正确，支付返回页可从“等待确认”恢复到成功或失败。
- 套餐和成员用量在不同组织间隔离显示。

### 运行验证

- `pnpm test`、`pnpm -r build` 与项目既有检查通过。
- 在 `manual` 模式跑通本地创建订单、模拟支付通知、订阅开通与权限恢复。
- 在支付宝沙箱环境使用真实验签跑通付款和异步通知后，才启用生产 `BILLING_PROVIDER=alipay`。

## 分阶段实施

1. 套餐目录、迁移、权益服务和写入保护，并完成 API 单元测试。
2. 组织订阅/账单页面、用量提示与只读体验。
3. 订单模型、手动本地支付渠道和端到端测试。
4. 支付宝 SDK、签名验收、回调路由、沙箱验证与生产部署文档。

支付宝真实密钥不会在代码、测试夹具或提交记录中出现。
