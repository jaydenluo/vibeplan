# Reliability Audit Remediation Design

## Goal

修复上一轮代码审查中已确认的用户可见 Bug、安全边界问题和数据一致性风险，并建立可重复的回归验证。

## Scope

1. 修复账单联系提示和执行报告错误提示的渲染，并同步修正受影响的测试 mock。
2. 将生产 CORS 改为显式 allowlist；生产启动缺少认证密钥时拒绝启动；为认证敏感接口增加独立限流。
3. 让工作项 PATCH 正确更新 `parentId`，校验父任务属于同一项目且不能形成父子循环；为已有数据补充父任务外键。
4. 为邀请链接增加撤销能力，并在接受过程中使用事务和条件更新避免竞态；保留现有可分享链接语义。
5. 统一依赖关系的持久化来源为关系表，同时兼容迁移已有 JSONB 数据并让查询、校验和同步保持一致。
6. 为账单订单创建增加组织级幂等/并发保护，避免重复 pending 订单。
7. 让迁移脚本以事务执行，并补充关键回归测试；E2E 仅在数据库可用时执行。

## Non-goals

- 不改变现有 UI 视觉设计和任务工作流语义。
- 不清理或覆盖工作区中与本次范围无关的既有改动。
- 不把测试环境数据库问题伪装成代码通过。

## Design

- 前端错误统一通过现有 `showMessage`/`MessageCenter` 展示，表单本地错误使用 `role="alert"`，确保可访问性和测试稳定性。
- CORS 从 `CORS_ORIGINS` 读取逗号分隔白名单，开发环境默认允许本地前端，生产环境无配置则拒绝启动。
- 认证接口使用独立 Fastify rate-limit scope，且不削弱全局限制。
- 父子关系在服务层事务中验证；数据库外键使用 `ON DELETE SET NULL`，防止删除父任务制造孤儿引用。
- 邀请接受使用 `UPDATE ... WHERE status='active' ... RETURNING` 与成员插入处于同一事务；增加管理员撤销路由。
- 依赖更新同时维护关系表和兼容字段，读取优先关系表；迁移脚本负责回填旧 JSONB 关系。

## Verification

- 先运行新增的定向测试，确认红灯，再实现至绿灯。
- 运行 `pnpm lint`、`pnpm build`、`pnpm test`。
- 数据库启动后运行 `pnpm test:e2e`；若数据库不可用，报告阻塞原因和已完成的替代验证。
