# 团队主入口与个人工作区菜单设计

## 目标

将“组织与团队”调整为以团队为中心的主导航入口，把组织和个人设置提升到左上角头像菜单中；同时简化组织、团队、项目创建表单，隐藏内部标识字段，并允许项目不填写 Git 地址。

## 用户体验

- 主导航显示“团队”，进入后展示当前组织下可见团队的卡片列表。
- 左上角显示当前用户头像（优先使用头像，没有头像时使用姓名或邮箱首字母）。点击后打开菜单，包含：个人资料、当前组织、组织切换、新建组织。
- 有多个组织时可在头像菜单中直接切换；切换后团队、项目和审批数据刷新到新组织上下文。
- 没有组织时，头像菜单和团队页面都显示“先新建组织”的明确入口。
- 组织、团队、项目创建只填写业务名称和必要关联关系，不要求用户理解 slug/标识。
- Git 地址改为选填。项目仍可创建；没有 Git 地址时，项目页面显示“未配置 Git，代码同步与仓库分析不可用”的能力提示。

## 数据与 API

- 组织、团队、项目继续保留内部 `slug` 字段，服务端根据名称和随机后缀生成唯一值，兼容现有记录和 CLI/API 返回结构。
- 创建组织 API 接收 `{ name }`；创建团队 API 接收 `{ name }`；创建项目 API 接收 `{ name, repositoryUrl? }`。
- `projects.repository_url` 改为可空，现有非空数据不变。
- 前端类型允许 `repositoryUrl` 为 `null` 或空值；所有展示位置使用“未配置 Git”替代空白。
- 头像菜单的组织切换复用现有组织列表接口；切换后由工作区统一刷新 teams/projects/items。

## 组件边界

- `WorkspacePage` 持有当前用户、组织和当前组织 ID，并负责组织切换后的上下文刷新。
- 新增 `ProfileMenu` 负责头像、个人资料入口、组织切换和无组织引导。
- `OrganizationPage` 收敛为团队列表/团队创建视图，不再作为主导航名称。
- `ProjectsPage` 的创建弹窗移除 slug 输入，Git 地址改为非必填，并展示能力提示。
- API access service 负责内部 slug 生成和可选仓库地址持久化。

## 错误与空状态

- 组织列表加载失败时，头像菜单保留个人资料入口并显示可重试错误。
- 没有组织时不显示空白团队列表，直接显示新建组织按钮和说明。
- 没有 Git 地址的项目可以正常进入任务管理；涉及代码同步的操作显示不可用原因，不阻止任务管理。
- 创建请求失败时保留表单内容并在表单内显示错误。

## 测试策略

- Web：验证主导航名称为“团队”、头像菜单打开、组织切换、无组织新建引导、创建表单不显示 slug、Git 地址可留空。
- API：验证创建组织/团队/项目时服务端自动生成唯一 slug；项目 repository URL 可为空；旧数据查询仍返回兼容字段。
- 全量运行现有 Vitest、TypeScript 检查、构建和 API 健康检查。
