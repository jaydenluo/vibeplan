# 工作台执行控制台设计

## 目标

把工作台从当前的空白/错误状态，完善为面向所有团队成员的组织执行控制台。用户打开工作台后，应能快速知道当前组织的项目健康度、风险任务，以及自己今天需要处理的事项。

## 已确认的产品决策

- 采用“执行控制台”布局，而不是纯项目驾驶舱。
- 工作台只展示当前选中的组织；切换组织后所有数据重新加载。
- 所有团队成员都可以使用工作台。
- 所有成员看到组织级健康摘要和自己相关的工作队列。
- 负责人/管理员额外看到审批、成员管理和订阅等管理入口；普通成员不显示这些管理操作。
- 网络/API 错误只通过全局 message 提示，页面不直接渲染 API 错误文本。
- 页面保留中性加载、空状态和重试操作。

## 当前问题与根因

前端请求以下两个已有 API 路由：

- `GET /organizations/:organizationId/overview`
- `GET /organizations/:organizationId/my-work`

当前页面收到 404，说明运行中的 API 进程或容器没有使用包含这些路由的最新构建，或者 Web 代理连接到了旧 API 服务。源码中路由和服务方法已经存在，因此实现需要同时验证 API 构建/部署版本、Web 代理目标和运行时健康检查，不能只隐藏前端错误。

## 页面结构

### 1. 页面头部

- 标题“工作台”和当前组织名称。
- 一句简短说明：当前风险、执行节奏和下一步工作。
- 刷新按钮，刷新组织总览和个人工作队列。
- 组织切换由现有全局组织选择器负责；页面不另造第二个组织选择器。

### 2. 组织执行摘要

四个紧凑指标：

- 进行中：当前组织正在执行的任务数。
- 待验收：等待审核/验收的任务数。
- 已阻塞：有阻塞依赖或被标记阻塞的任务数。
- 已逾期：超过计划日期仍未完成的任务数。

指标可点击跳转到项目管理或审批页面，沿用现有路由和权限控制。

### 3. 项目健康度

按当前用户可见项目列出：

- 项目名称和任务数量。
- 项目整体完成度。
- 进度条。
- 风险摘要：阻塞、逾期、停滞；无风险时显示“进展正常”。

点击项目进入项目管理页。空组织显示“当前没有可访问的项目”和创建/进入项目管理的引导。

### 4. 今日工作

按当前登录用户聚合显示：

- 进行中：优先继续已开始的任务。
- 可开始：前置依赖满足、可以开始的任务。
- 被阻塞：显示阻塞来源。
- 待验收：当前用户有审核权限且需要处理的任务。
- 建议下一步：从进行中或可开始队列中选出一项。

每个任务显示项目、优先级、截止日期和系统生成的原因，点击直接打开对应项目任务。

### 5. 管理入口

只对负责人/管理员显示入口：

- 待办审批。
- 团队成员与权限。
- 组织订阅与账单。

不在工作台复制管理页面的数据表，只提供明确入口，避免信息过载。

## 数据流与接口

1. `WorkspacePage` 维护当前选中的 `organizationId`。
2. `OrganizationOverview` 请求 `/organizations/:organizationId/overview`，展示组织级摘要和项目健康度。
3. `TodayWork` 请求 `/organizations/:organizationId/my-work`，展示当前登录用户工作队列。
4. 切换组织或点击刷新时，两块数据重新请求。
5. API 失败由 `apiRequest` 统一发出 message；组件只设置中性空状态和重试可用状态，不保存或渲染服务端错误文本。
6. 部署验证必须确认 API 镜像包含上述路由，并通过 Web 容器的 `/api` 代理访问；不允许通过修改前端 URL 掩盖旧 API。

## 错误与空状态

- 加载中：显示轻量加载提示。
- 没有组织：提示选择组织。
- 组织无项目：显示空状态和进入项目管理的动作。
- 请求失败：显示全局 message，页面显示中性空状态与“重试”。
- 业务只读/订阅宽限期：保留业务警告，因为这不是网络错误。
- 不显示 `Request failed with 404`、服务端原始错误或异常堆栈。

## 实现范围

- 修复本地/线上 API 构建与部署验证，使两个工作台接口可用。
- 完善工作台组件结构、响应式布局和错误/空状态。
- 按权限显示管理入口。
- 补充 API 路由、工作台组件和 message 行为测试。
- 不新增独立数据库表；复用现有项目、任务、事件和成员数据。

## 测试与验收

- API：已认证组织成员可读取两个接口；非成员被拒绝；接口返回结构稳定。
- Web：组织总览指标、项目风险、个人队列、组织切换和刷新行为正确。
- Web：接口 404/500 时只出现全局 message，页面不出现原始错误文本。
- Web：普通成员隐藏管理入口，负责人/管理员显示管理入口。
- Build：Web、API 和 CLI 构建通过。
- 部署：运行中的 API `/health` 正常，Web 代理访问两个工作台接口不再返回 404。

## 风险

- 线上旧镜像可能继续运行，即使本地源码已有路由；部署验证必须记录镜像版本或构建提交号。
- 个人工作队列依赖当前成员对项目的可见性和贡献权限，不能把不可见项目混入组织摘要。
- 组织切换期间旧请求可能晚于新请求返回，需要用请求生命周期或组件卸载保护避免旧数据覆盖新组织。
