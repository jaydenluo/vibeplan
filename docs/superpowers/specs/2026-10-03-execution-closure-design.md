# VibePlan 执行闭环增强设计

## 目标

将 VibePlan 从任务记录工具补齐为可执行、可追踪、可复盘的项目管理闭环：任务有详细计划，进度可解释，风险可发现，依赖和里程碑可管理，成员贡献可复盘。

## 范围

本次分四个独立模块实现：

1. 任务详细计划 Markdown：数据库保存正文，Web 只读展示，CLI 生成 `.plan.md` 镜像。
2. 自动进度和风险：子任务加权汇总、计划/实际偏差、逾期/停滞/落后风险和筛选。
3. 依赖、里程碑和健康度：依赖编辑与阻塞来源，项目里程碑，项目健康摘要。
4. 贡献统计增强：实际工时、工作日志、验收通过率和时间范围统计，同时兼容历史任务。

## 数据模型

- `work_items.plan_markdown`：可为空的 Markdown 正文。
- `work_items.actual_hours`：可为空的非负数，历史任务保持为空。
- `work_item_work_logs`：任务、成员、工时、日志内容、发生日期和创建时间。
- `project_milestones`：项目、名称、描述、目标日期、状态。
- `work_item_milestones`：任务与里程碑关联。
- 依赖继续使用现有 `work_item_dependencies`，并通过 API 读写，不再维护重复 JSON 关系。

## 服务端行为

- 返回任务时附带 `progressSummary` 和 `riskFlags`，但不覆盖数据库中的手动进度。
- 有子任务的父任务使用子任务预估工时加权进度；没有子任务时使用手动进度。
- 任务开始日期取第一次进入 `in_progress` 的事件时间；没有明确排期时，开始后按预估工时计算结束日期。
- 风险计算为纯函数：逾期、停滞（超过 3 天无更新且未完成）、进度落后（时间消耗超过进度 20 个百分点）。
- 任务开始时，如果存在未完成依赖，返回可理解的阻塞错误并列出阻塞任务。
- 贡献统计按筛选日期范围聚合实际工时；没有实际工时时，继续按预估工时乘进度增量折算。

## Web 行为

- 任务详情增加只读计划 Markdown 区域，使用现有安全文本渲染，不执行 HTML。
- 任务创建/编辑增加计划 Markdown、里程碑、依赖和实际工时入口。
- 任务目录显示风险标识和阻塞来源，项目页提供风险筛选。
- 项目页显示里程碑和健康度摘要。
- 成员贡献弹窗增加日期范围、实际工时、验收通过率和工作日志汇总。

## CLI 与同步

- 任务镜像继续写入 `.vibe/tasks/<id>.md`。
- 计划正文单独写入 `.vibe/tasks/<id>.plan.md`，避免旧工具解析 front matter 时受影响。
- daemon 继续自动同步；计划文件只从云端写入本地，网页端只读。

## 兼容与安全

- 新字段均可为空或有默认值，旧任务可以继续读取和同步。
- 所有新增 API 继承项目访问权限和版本冲突校验。
- Markdown 只作为文本展示，禁止原始 HTML 和脚本。
- 删除任务时级联删除工作日志、依赖关联和里程碑关联。

## 验证标准

- API、Web、CLI 测试覆盖新字段、风险计算、依赖阻塞、计划镜像、工时和贡献聚合。
- `vibeplan check`、`pnpm lint`、`pnpm test`、`pnpm -r build` 全部通过。
